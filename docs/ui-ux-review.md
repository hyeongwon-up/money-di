# UI/UX 개선 기록

## 프로젝트 구조

- 프론트엔드: React 18, Vite, Tailwind CSS, Recharts, Axios
- 백엔드: Spring Boot, 자산·자산 이력·생각·지출 계획 API
- 주요 화면: 비밀번호 진입, 자산 현황, 계층형 생각 정리, 지출 및 납부 계획

## 우선 문제와 반영 사항

| 문제 | 개선 |
| --- | --- |
| 상단 메뉴에 금액과 내비게이션이 밀집 | 자산 요약 카드를 본문 상단에 배치하고 모바일 메뉴를 별도 행으로 구성 |
| 자산 등록 폼이 화면 하단에 위치 | 상단 등록 버튼에서 폼으로 이동하고 자산명 입력에 포커스 |
| 동일 자산을 수정하는 폼이 두 곳에 표시 | 기존 등록 폼을 수정 폼으로 전환하는 단일 편집 흐름 |
| 긴 자산 목록에서 항목 찾기 어려움 | 자산명·금융사·메모 검색, 검색 결과 개수 및 빈 상태 |
| 수정·삭제 기능이 마우스 호버에 의존 | 버튼 상시 표시, 접근 가능한 이름, 자산 목록 터치 영역 확보 |
| 조회 실패와 실제 데이터 없음 구분 부족 | 로딩·오류·빈 상태 구분, 재조회 버튼, 이전 자산 데이터 유지 |
| 저장 실패 후 결과 확인 어려움 | 자산 저장 결과 및 오류 안내, 입력 보존, 저장 중 입력/중복 제출 제한 |
| 차트 비중이 같은 항목의 금액 표시 오류 | 비중 라벨에 해당 비중만 표시, 금액은 툴팁에서 확인 |
| 차트 금액 해석 불명확 | 절댓값 기준 표시, 현재 부동산·대출을 차감한 과거 추이의 추정치 안내 |
| 모바일 지출 카드와 생각 답글 영역 밀집 | 지출 요약/목록 세로 배치, 생각 답글 들여쓰기 축소 및 액션 줄바꿈 |
| 입력 라벨·키보드 접근성 부족 | 폼 라벨 연결, 선택 필터 상태, 포커스 표시, 본문 건너뛰기, 모션 감소 설정 대응 |

기존 LOAN 카테고리는 화면에서 DEBT로 통합해 자산 목록과 분포에 누락되지 않게 했습니다.
지출 예정일 계산은 로컬 날짜 기준으로 맞췄습니다.

## 검증

- `npm --prefix frontend run build`: 통과. 기존 큰 번들 크기와 Browserslist 갱신 경고는 남아 있습니다.
- `git diff --check`: 통과.
- 실제 브라우저: 데스크톱 자산 화면 및 390 × 844 모바일 자산·지출·생각 화면 확인.
- 세 화면 모바일 문서 폭이 390px로 가로 넘침 없음 확인.
- 자산 검색 결과 없음, 검색어 삭제 후 목록 복원, 등록 폼 이동/포커스 확인.
- 자산 수정 폼이 하나만 표시되고 취소하면 등록 모드로 돌아오는지 확인.
- 브라우저 마지막 오류 로그 조회에서 오류 없음.
- `npm --prefix frontend run lint`: 기존 ESLint 설정 파일이 없어 실행 불가.
- 실제 API의 저장·삭제 요청은 실행하지 않았습니다. 쓰기 실패/재시도 및 서버 장애 상태는 코드 검토만 진행했습니다.

## 후속 개선 후보

- 브라우저 기본 prompt를 사용하는 자산 이력 수정을 접근 가능한 편집 UI로 교체.
- 생각 답글 작성 시 대상 내용을 작성창에 표시.
- 지출 계획에 미납·완료·기한 경과 필터 추가.
- 차트 및 화면 분할 로딩으로 초기 번들 크기 개선.
